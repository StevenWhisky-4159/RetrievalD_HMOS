# 文档评分模式 Sample 400 对比分析

## 实验设置

- 原始数据集：`dataset/dataset.xlsx`，共 4057 条有效数据。
- 抽样数据集：`dataset/sample_400.xlsx`。
- 抽样方式：`pandas.DataFrame.sample(n=400, random_state=2026)`。
- 检索范围：`harmonyos-guides/`。
- 检索粒度：Markdown 文档级。
- 返回数量：Top 10。
- 文档平均分统计全部分片，未命中分片按 `0` 分计算。
- `weighted` 最高分片权重为 `0.5`，平均分权重为 `0.5`。

三个模式使用完全相同的 400 条 query：

- `max`：文档得分等于最高分片得分。
- `weighted`：`0.5 × 最高分片得分 + 0.5 × 全部分片平均分`。
- `max_plus_sum`：`(最高分片得分 + 全部分片得分和) / (分片数 + 1)`。

结果文件：

- `data/document_sample_400_max.json`
- `data/document_sample_400_weighted.json`
- `data/document_sample_400_max_plus_sum.json`

- Hit@3：91.00%

### weighted

- Hit@1：69.25%

- Hit@10 增加 0.50 个百分点。
- MRR 增加 0.0145。
- 50 条 query 排名改善，26 条退化，324 条不变。

### max_plus_sum

- Hit@1：66.25%
- Hit@3：89.50%
- Hit@5：94.75%
- Hit@10：98.00%
- MRR：0.7888

与 `max` 相比：

- Hit@1 降低 1.75 个百分点。
- Hit@3 降低 1.50 个百分点。
- Hit@5 降低 0.25 个百分点。
- Hit@10 增加 0.50 个百分点。
- MRR 降低 0.0081。
- 59 条 query 排名改善，49 条退化，292 条不变。

## 配对 bootstrap

对同一批 400 条 query 进行 20000 次配对 bootstrap，随机种子为 2026。

`weighted - max`：

- Hit@1 差值 95% CI：[-2.00, +4.50] 个百分点。
- MRR 差值 95% CI：[-0.0039, +0.0332]。
- bootstrap MRR 差值为正的比例约为 93.56%。

`max_plus_sum - max`：

- Hit@1 差值 95% CI：[-5.75, +2.00] 个百分点。
- MRR 差值 95% CI：[-0.0326, +0.0158]。

两个区间均跨过 0。本次 400 条结果能够说明趋势，但尚不足以确认稳定提升，
建议继续使用完整 4057 条数据或多个随机种子复验。

## 文档分片数影响

三种包含平均分的算法都会引入文档长度偏置，因为未命中分片以 `0` 分参与平均。

### 单分片文档（139 条）

- max Hit@1：50.36%
- weighted Hit@1：59.71%
- max_plus_sum Hit@1：64.03%

单分片金标本身的三种得分相同，但其他多分片候选会受到平均分惩罚，因此单分片
文档的相对排名明显上升。

### 2–3 分片文档（95 条）

- max Hit@1：77.89%
- weighted Hit@1：72.63%
- max_plus_sum Hit@1：72.63%

### 4–10 分片文档（127 条）

- max Hit@1：75.59%
- weighted Hit@1：74.02%
- max_plus_sum Hit@1：68.50%

### 11 个及以上分片文档（39 条）

- max Hit@1：82.05%
- weighted Hit@1：79.49%
- max_plus_sum Hit@1：51.28%

`max_plus_sum` 的最高分片相对权重随文档长度快速下降。对于分片数为 `n` 的文档，
最高分片在公式中的直接权重约为 `2 / (n + 1)`，因此长文档退化尤其明显。

## 典型变化

`weighted` 的主要改善：

- 音频流类型选择：未进入 Top 10，提升至第 5。
- 状态管理（V1）：未进入 Top 10，提升至第 5。
- ohpm 常见错误码：第 7 提升至第 2。
- ArkTS 模块动态与延迟加载：第 4 提升至第 1。

`weighted` 的主要退化：

- Code Linter `no-unsafe-return`：第 1 降至第 6。
- C/C++ 相机微距能力：第 7 降至未进入 Top 10。
- Network Kit 简介：第 1 降至第 4。

`max_plus_sum` 的主要退化：

- TaskPool 任务不执行：第 1 降至未进入 Top 10。
- AVCodec 支持格式：第 3 降至第 10。
- 应用开发准备：第 5 降至未进入 Top 10。
- IAP 商品信息配置：第 1 降至第 6。

## 结论与建议

1. 当前 400 条样本中，`weighted(0.5/0.5)` 的总体指标最好，可作为候选模式。
2. `max` 对多分片和长文档最稳定，仍应保留为默认基线。
3. `max_plus_sum` 虽能改善部分概览型 query，但对长文档惩罚过强，不建议作为
   全局默认模式。
4. 下一轮建议测试 `max_score_weight=0.6、0.7、0.8、0.9`，并继续按文档分片数
   分层报告，寻找单分片收益与长文档稳定性之间的平衡。
5. 在切换默认模式前，应运行完整 4057 条评测或多个随机种子，并检查退化样例
   是否集中在 FAQ、概览页、长文档或特定目录。
